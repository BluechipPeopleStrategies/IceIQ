Legal vs. illegal lane marker

02

Both passes use the identical gold dashed "correct read" line style from panel 1 — color alone never signals legality here (the code's own accessibility rule). A pass judged offside gets a small red hazard mark at the exact blue-line crossing, plus the same white/gold cue-pill shape already used for coach callouts, recolored red.

Proposed

Legal vs. illegal lane marker

  • Hazard diamond at the infraction point, not the whole route
  • Red-bordered cue pill, same shape as the gold coaching pill
  • Route color stays gold — legality is shape + label, never a red/green pass line

Ties to TASKS.md: "Rule-legality awareness in content (offside, icing)" — Best Option now deliberately generates offside passes but has no on-ice marker yet.

Surface-conditional per the roadmap note: half-ice U9 content has no offside, so this marker only ever appears on full-ice scenarios.

Goalie state — set vs. moving

03

The goalie keeps its shipped rounded-rect token in both states. "Set" adds a faint stationary ring (reads as "planted"); "moving" reuses the existing ghost-trail technique from outcome playback plus the gold direction arrow already used for motion cues — no new drawing primitives, just a new combination of existing ones.

Proposed

Goalie state — set vs. moving

  • Set: token + static dashed ring, no trail
  • Moving: 3-frame opacity ramp (0.35 → 0.6 → 1.0) + gold direction arrow
  • Reuses the outcome ghost-trail already built for play playback

Ties to TASKS.md LATER: "Goalie-reading concept (triage theme 4) — new ledger concept/node + goalie-state representation (set vs moving)."

Consequence chain — two-read branch

04

The rink chrome, tokens and route strokes are untouched — this is a flow diagram laid over three mini rink insets rather than a new drawing style. Solid connector = the read that follows a correct first decision, dashed = the read that follows an error, converging back to one question length either way.

Proposed

Consequence chain — two-read branch

  • 3 decision nodes per play, fixed length, branches reconverge
  • Solid navy connector = correct-branch continuation
  • Dashed navy connector = error-branch continuation
  • "Right"/"wrong" text color is UI chrome only — never painted onto the rink itself

Ties to TASKS.md LATER: "Consequence chains (two-read plays)" — outcome nodes already route via setNodeId(opt.next); this is the missing visual, not new engine work.
