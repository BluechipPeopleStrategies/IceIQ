- **Skip a question and come back.** Requested by Thomas 2026-08-03 after being trapped on a broken question with no way past it: a defective or confusing question currently makes the whole session unfinishable, which is far worse than the defect itself. **DECIDED by Thomas 2026-08-03: a skip counts WRONG, and the question stays available to come back to.** So the result is recorded as incorrect immediately (no free pass, no farming a perfect score by skipping the hard ones) but the question is re-queued rather than consumed, and answering it later REPLACES the provisional wrong result. That replacement is the fiddly part: `results` is keyed by position, not question id, so revisiting has to update the existing row rather than append — appending is exactly the double-record bug fixed on 2026-08-02. Original framing: Excluding it is the honest reading (the player made no read) but it lets a player farm a perfect score by skipping anything hard, so a cap or a "skipped" tally on the results screen probably has to come with it. Note the denominator is `results.length`, which is shared with `calcWeightedIQ()` — the same array that caused the 2026-08-02 scoring bug — so whichever way it goes, it has to be decided at the point the result is recorded, not patched onto the display. Size: small once the call is made.
- **"How to play" first-run walkthrough, interactive rather than text.** Requested by Thomas 2026-08-03. The right granularity is **per interaction kind, not per game** — there are five primitives (`point` tap-a-spot, `selection` tap-a-player, `place` drag-and-check, `path` draw-a-route, `sequence` order-the-steps) and each has genuinely different mechanics. A player meeting `place` for the first time has no way to know the tokens are draggable, which is part of why "I can't drag the players" was ambiguous between a bug and a UI gap (it turned out to be a real bug, but the ambiguity is the point). Suggested shape: first time a player meets a kind, a short guided overlay that has them perform the action once on a throwaway example before the real question starts, then never shows again for that kind (per-player flag). Ties into the existing `youngQ`/`youngT` age-banded copy — U7–U11 need this more and need it wordless. Size: small-to-medium per kind, and they can ship one at a time.
- **Rule-legality awareness in content (offside, icing).** Raised by Thomas 2026-08-03 on the Brain Gym "Best Option" drill: an option can be tactically sensible but illegal, and the question has to be mindful of that. This is the second live instance of the gap identified 2026-08-01 — **no validator anywhere checks whether a depicted or chosen play is legal**; every gate we own checks physically-possible, visually-clean, novel, or sourced. Note it is surface-conditional: Hockey Canada half-ice U9 has no offside or icing at all, so any check keys off the surface model (also parked). **DECIDED by Thomas 2026-08-03: teach offside rather than avoid it.** The Best Option generator should deliberately produce positions where a pass is available but illegal, making CARRY the right read *because* the pass is offside. That converts the defect into the only content we have that teaches the rule, and needs a fourth feedback line explaining why. See `docs/factory/2026-08-03-best-option-positioning.md`. Cheapest first step is still a content review pass over options involving passes across a blue line. Size: unknown until the review happens.
- **Consequence chains (two-read plays). DEFERRED by Thomas 2026-08-02** — playtest backlog first; finding and fixing what is already broken beats adding a mechanic on top of it. Design, agreed in conversation and recorded here so it is not lost: **the branching engine already exists and is 100% unused by content.** `AnimatedPlay.jsx` already does `setNodeId(opt.next)` and every play already routes different answers to different outcome nodes (`dz_breakout_escape_pressure` has six). What is missing is only that those outcome nodes are `terminal: true` — the consequence *ends* instead of asking again. A chain is therefore **pure data, no engine work**: drop `terminal: true` from an outcome node, give it an `ask`, point its options at two new terminals. Agreed shape: **2 reads, branches converge** — promote two outcome nodes (one after a right read, one after a wrong one) into second decisions that arrive at the same question from different circumstances, 3 decision nodes per play, fixed length so scoring and telemetry stay simple. Scope was 4 retrofits, U13+ only (U7–U11 keep single reads; the `youngQ`/`youngT` copy exists because that band needs less load). Authoring rule: the second read must be a genuinely different decision — if the wrong branch's second read is obvious *because* you know you erred, it is a scold with extra steps. **Verify before authoring:** whether `validateFactoryStandards` / `artLint` / the decision-richness gate assume one decision node per play, and how scoring handles it — the latter matters more now that `results` turned out to be shared with `calcWeightedIQ()`. Size: days, mostly content.
- **Surface model / age-appropriate ice personalization.** Plays declare a surface (`cross-ice` / `half-ice` / `full-ice` / `zone-local`), players and teams declare the surface their program plays on, and serving filters on the match. Design + the correction that reshaped it: `docs/superpowers/specs/2026-08-02-surface-fit-validator-design.md`. **Deferred 2026-08-02, no live defect to fix:** the catalog was measured and its largest footprint across all 25 plays is 55ft x 44ft, so every play already fits both a U9 half-ice surface (100x85) and a U7 cross-ice area — `space.units: "rink-200x85"` is the coordinate frame, not a footprint.
