# Cognitive Gym Expansion: Points, Intros, Scoring Rework, and 5 New Games

Date: 2026-06-13
Status: Design approved (slate + architecture). Pending user review of this written spec.
Owner: Thomas

## Context

The Cognitive Gym (`src/cognitive-gym/`) currently ships three procedurally
generated brain-training drills: Read the Pass (anticipation), Head on a Swivel
(multi-object tracking / awareness), and Shoot or Hold (go/no-go reaction). They
share one adaptive engine (`gymEngine.js`), one storage module (`gymStorage.js`),
and a hub (`CognitiveGym.jsx`) driven by a `DRILLS` registry.

This expansion does four things in one batch:

1. Add a gym-wide **points system** scored on how well you actually perform,
   not just pass/fail.
2. Overhaul the **intros** so each game opens with a clear goal and a real
   hockey reason, plus a short gym-wide intro on the hub.
3. Rework **Read the Pass** scoring to be graded by accuracy (GeoGuessr-style),
   with a bigger gold target bar and a much smaller success window.
4. Add **5 new games** (Snapshot, Find the Lane, Best Option, Eyes Up, Read the
   Numbers), proving both an abstract-canvas pipeline and a real-rink-art
   pipeline.

Two further games (Late Read, Two Things at Once) are designed conceptually but
deferred to a later batch.

## Goals

- Reward precision, not just "inside the ring." Closer is worth more.
- Give every game a clear "what am I trying to do and why does it matter on the
  ice" intro in Thomas's voice, kid-friendly for U7 to U18.
- Keep the zero-content-maintenance philosophy: every rep generated by code.
- Reuse the existing engine, storage, registry, and phase pattern. No new
  dependencies.

## Non-goals

- No Supabase backend for the gym yet (storage stays local, as today).
- No leaderboard or social comparison. Points are personal progress only.
- Not building Late Read or Two Things at Once in this batch.
- Not citing IntelliGym / NeuroTracker / Velocity branding or their validated
  study results. These are original drills inspired by the same cognitive
  domains. (See the marketing guardrail in `cognitive-gym/README.md`.)

## Architecture

Reused as-is:

- `gymEngine.js`: `createAdaptiveLevel` (3 up / 2 down, levels 1-20), `levelT`,
  `lerp`, `rand`, `setupCanvas`, `drawRink`, `pointerPos`.
- `gymStorage.js`: per-player, per-drill records in `localStorage`
  (`rinkreads_gym_v1`), extended for points (see Storage).
- `CognitiveGym.jsx`: hub + `DRILLS` registry, extended with new fields.
- The `intro / playing / done` phase pattern each drill already follows.
- `cognitive-gym.css`.

Two rendering pipelines:

- **Canvas pipeline** (Eyes Up, Read the Numbers): the existing pattern. A
  `<canvas>` sized by `setupCanvas`, drawn in a `requestAnimationFrame` loop,
  taps via `pointerPos`. `drawRink` optional per game.
- **Rink pipeline** (Snapshot, Find the Lane, Best Option): a new helper
  `gymFormations.js` generates valid `{ stage, actors, answer }` for a level,
  rendered through the real `RinkStage` (SVG, 600x300 viewBox, shape-coded
  markers that are already colorblind-safe). Interaction is an overlay supplied
  through `RinkStage`'s children render-prop. Generated, not authored, so still
  zero content upkeep.

Registry entry shape (extended):

```js
{
  id, name, skill,
  blurb,            // existing one-liner on the card
  goal,             // NEW: "Your goal:" plain-language objective
  why,              // NEW: the real hockey moment it trains, Thomas's voice
  trains,           // existing skill-transfer text (kept, may be folded into `why`)
  build,            // NEW: 'canvas' | 'rink'
  component,
}
```

`goal` and `why` are the single source of truth: the hub card previews `goal`,
and each game's intro screen shows `goal` first, then mechanics, then `why`.

## Points system (graded, GeoGuessr-inspired)

Today a session score is `hits / ROUNDS * 100` (binary per rep). The new model
grades each rep by accuracy and accumulates points.

Per rep, a game returns two values:

- `success: boolean` -> still drives `createAdaptiveLevel` (level up/down). A
  rep is a success only if it lands inside the (now small) success window.
- `repPoints: number` (0..`MAX_REP`, `MAX_REP = 1000`) -> graded by accuracy.

Graded curve (GeoGuessr-style exponential decay). For an accuracy game with a
normalized error `e` in `[0, 1]` (0 = exact, 1 = worst):

```
repPoints = round(MAX_REP * exp(-e / DECAY))
```

`DECAY` is a tunable constant (start at `0.12`): exact = full 1000, `e = 0.12`
gives about 370, `e = 0.25` gives about 120, then it tails toward 0. Bang-on
clearly beats barely-right, and being just inside vs just outside the success
window is a smooth difference in points rather than a cliff.

Aggregates:

- **Session points** = sum of `repPoints` over the session's reps
  (0..`ROUNDS * MAX_REP`). Shown on the done screen.
- **Best points** per drill (replaces / sits beside the existing `best`).
- **Career points** = sum of session points across all drills, shown on the
  hub as a new stat next to streak / sessions / days. This is the "points
  piece" the player watches grow.

Per-rep points float up on screen as visual feedback (e.g. "+870") when the
reveal resolves.

The adaptive level and the points are intentionally decoupled: the small
success window keeps leveling honest (you must be genuinely accurate to climb),
while graded points reward every bit of precision.

## Read the Pass rework

File: `AnticipationDrill.jsx`. Three changes.

1. **Bigger gold bar.** The crossing target is currently a 4px vertical line at
   `targetX`. Render it instead as a wider vertical band (a "gold bar"), width
   about 18 to 28px, so it is an obvious, larger thing to aim at. The full
   height stays tappable (it already is via `handleGuess` reading `pos.y`).
2. **Much smaller success window.** `tolerance` is currently
   `H * lerp(0.16, 0.06, t)` (16% of rink height at level 1 down to 6% at top).
   Tighten to roughly `H * lerp(0.075, 0.02, t)` so a "hit" (for leveling)
   demands real precision. Final numbers tuned by play-test.
3. **Graded scoring by closeness.** Compute `d = abs(guessY - crossY)`,
   `e = clamp(d / H, 0, 1)`, then `repPoints` from the curve above. The reveal
   already draws the tolerance ring and the guess marker; add the points float
   and a faint line from the guess to the true crossing so "how close was I"
   reads visually, GeoGuessr-style.

Session score display switches from "X of 8 on target" to session points (with
the hit count kept as a secondary line). Level still moves on the binary
success flag.

## The 5 games

Each: one component file, registered in `DRILLS`, `intro / playing / done`
phases, adaptive level, returns `{ success, repPoints }` per rep.

### Snapshot (rink) - perception span
A formation flashes for a short window (about 600ms at low level), then hides.
Tap where your open teammate was. `success` = tap within the small window of
the true position. `repPoints` graded by distance. Level scales: flash duration
shrinks, more decoys/defenders, tighter spacing.

### Find the Lane (rink) - spatial pattern recognition
A static formation of teammates and defenders. Exactly one clean passing lane
is open. Tap it before it closes (a countdown). `success` = correct lane in
time. `repPoints` graded by remaining time and tap precision toward the lane's
center. Level scales: more defenders, narrower seams, faster close.

### Best Option (rink) - decision speed
A play freezes with the puck on your stick. Three labeled options (shoot / pass
to a teammate / carry) are offered. Pick the best one before a tightening clock.
`success` = correct option in time. `repPoints` graded by reaction speed. Level
scales: shorter clock, less obvious best option, more plausible decoys. This is
the most engine-overlapping game; it reuses formation generation but its own
lightweight "best option" rule, not the scenario bank.

### Eyes Up (canvas) - peripheral vision
Fixate a center puck (a small fixation target stays lit center-screen). A
teammate flashes briefly in the periphery; tap the side it appeared (or the
quadrant). `success` = correct side while fixation held. `repPoints` graded by
reaction time. Level scales: shorter flash, wider eccentricity, more
distractors.

### Read the Numbers (canvas) - dynamic visual acuity
A jersey number streaks across the ice; read it back (tap the matching number
from a small set, or it briefly stays then you pick). `success` = correct
number. `repPoints` graded by how long the number was visible before you locked
in. Level scales: faster streak, more digits, shorter visibility, closer
decoys.

## Intro overhaul

1. **Gym-wide intro** on the hub: a concise, always-visible block above the grid
   (heading + 2 to 3 sentences on what the gym is, plus 3 short "how to use it"
   bullets: short sessions, 2 to 3 times a week, levels adapt to you). Always
   visible so it is findable later, not a one-time popup.
2. **"Your goal:" line** first in every game's intro, plain and kid-friendly,
   separate from the "The game:" mechanics that already exist.
3. **Stronger "why it matters"** block: the real hockey moment, warm and
   growth-oriented, in Thomas's voice. Replaces the dense current "On the ice"
   text where it is too jargon-heavy.

All three drive off the registry `goal` / `why` fields.

## gymFormations.js (rink pipeline helper)

New pure module. Exports a generator that, given a level and a game variant,
returns:

```js
{
  stage,            // RinkStage `stage`/view (e.g. 'neutral', 'full')
  actors,           // array of { kind, x, y, label? } in normalized coords
  answer,           // game-specific truth: open teammate pos / open lane / best option
  meta,             // anything the game needs (e.g. decoy ids)
}
```

It respects the engine's marker rules (U7/U9 generic players, U11+ labeled) and
places non-overlapping actors within the rink bounds. Pure and deterministic
given a seed, so it is unit-testable without a browser.

## Data flow (rink game)

`start()` -> `createAdaptiveLevel` from stored level -> per rep:
`gymFormations.generate(level, variant)` -> render `RinkStage` with overlay ->
tap -> compute `{ success, repPoints }` -> `engine.record(success)`,
accumulate points -> reveal -> next rep -> on last rep `saveSession` with
`{ score, points, level, meta }`.

## Storage changes

`gymStorage.js` session shape gains `points`:

```
{ date, score, points, level, meta }
```

- `saveSession` writes `session.points` and tracks `bestPoints` alongside
  `best`. Backward compatible: old sessions lack `points`; treat missing as 0.
- `getStats` adds `careerPoints` = sum of `points` across all sessions of all
  drills for the player.

No destructive migration. The single `rinkreads_gym_v1` key and per-player /
per-drill structure are unchanged.

## Testing

- New pure helpers get vite-free unit tests like the rest of the gym:
  - `gymFormations`: generated actors stay in bounds, do not overlap, exactly
    one valid answer where required, marker rules per age.
  - Points curve: monotonic decreasing in error, exact = `MAX_REP`, clamps.
  - `getStats.careerPoints` sums correctly and ignores legacy point-less
    sessions.
- Interactive components are play-tested in dev (`#scenarios`-style manual
  pass, opened via the gym hub).

## Build order

1. Points system plumbing + storage + hub career-points stat + registry
   `goal`/`why`/`build` fields + the gym-wide intro and the per-game intro
   template. (Touches shared files; do first.)
2. Read the Pass rework (bigger bar, smaller window, graded points). Smallest
   change to an existing game, validates the points model end to end.
3. The 2 canvas games (Eyes Up, Read the Numbers).
4. `gymFormations.js` + the 3 rink games (Snapshot, Find the Lane, Best Option).

Play-test after each step. Each step is independently shippable.

## Guardrails

- Voice: warm, growth-oriented, sounds like Thomas. No em dashes in any
  player-facing copy.
- Audience: U7 to U18. Keep language concrete and encouraging.
- Accessibility: never rely on color alone. RinkStage markers are already
  shape-coded; canvas games must pair any color signal with shape, icon, or
  label.
- Marketing: inspired-by language only. No competitor branding or borrowed
  study results.

## Decisions made during design

- First batch = 5 games (Snapshot, Find the Lane, Best Option, Eyes Up, Read the
  Numbers) plus the intro overhaul, points system, and Read the Pass rework.
- Rink games use the real `RinkStage` art, not the lighter `drawRink` canvas.
- Points and leveling are decoupled: small success window for leveling, graded
  GeoGuessr-style points for precision.

## Open questions

- Exact `DECAY`, `MAX_REP`, gold-bar width, and tolerance numbers are starting
  points to be tuned by play-test.
- Whether "career points" should also surface outside the gym (e.g. on the
  player home). Out of scope for this batch unless you want it.
