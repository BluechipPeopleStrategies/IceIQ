01 / Current implementation

From an answer
to a team average.

The real team card reads saved quiz history. It measures answer accuracy in positioning, decision-making, awareness, tempo control and leadership.

1

Save the quiz answer

Question ID, category, correctness, difficulty and format are stored. Session history adds a date. Full first-exposure and selected-answer histories are generally absent.

2

Map to a competency

The current resolver recognises old question-ID patterns. A separate rule puts every “What happens next?” answer into leadership. It does not resolve the modern concept ID.

3

Average the players

Each player gets a percentage. The team calculation averages positive player percentages equally. It currently omits a measured 0% as well as missing evidence.

03 / Repair before relying on it

Two important
measurement gaps.

These are current implementation findings. Adding practice points to the existing formula would not fix either one.

Question mapping
0 of 262 bank IDs match

The report expects older IDs.

The current question bank uses newer IDs. 156 questions have a concept ID, but the competency resolver does not use it. Twenty-eight additional scenario seed files also use newer IDs.

The 17 “next” questions can still enter leadership through a separate format rule. That does not establish leadership as what each question measures.

Evidence handling
0% is currently excluded

Measured zero and missing collapse.

The average drops both. The below-60% count can include both. A roster containing only a player with measured zeros even returns zero active players in the no-populated-competency branch.

A fixed accuracy cutoff also does not establish a developmental norm for an age group.

Which time window?
All fetched history for current roster players. No date, age-band or team-join filter. “Focus this week” does not mean the bars use only this week.
First attempts or repeats?
Every saved row counts equally. No freshness or distinct-situation adjustment. A skipped placeholder may be replaced later, so old rows are not a full first-response log.
How much evidence is enough?
No per-competency minimum exists. One correct answer can contribute 100%. The individual report’s three-session unlock is a separate display rule.
Are coach ratings included?
No. Coach, parent and self-ratings appear separately in a player’s profile. They do not affect these quiz-derived team percentages.
Do difficulty or speed help?
Not in team competencies. The separate session score uses difficulty weights 1, 1.5 and 2.2. Speed bonus does not enter that score.
What about the Team accuracy tile?
That separate analytics tile pools answers across players. It also compares the recent seven days against the previous seven. It is not this competency calculation.

Changing the camera, wording or option order does not create a new hockey decision. Draft drag regions, ungraded coach placements and factual observation questions are useful practice, but they do not automatically prove tactical mastery. Explanations remain optional.

Exact current paths and formulas
  • App.jsx: landing sample literal values; toggleRoster fetches current players and their sessions; TeamFocusCard calls calcTeamCompetencyAverages. The landing 50% threshold is sample text, distinct from the real fixed 60% rule.
  • gameSense.js: getQuestionCompetency returns the first matching legacy ID pattern. calcCompetencyScores counts unweighted answer rows and independently adds all type: 'next' rows to leadership. calcGameSenseScore averages five competency percentages, including unobserved zeros.
  • coachStats.js: calcTeamCompetencyAverages averages rounded player percentages only when v > 0. Weakest is the lowest populated competency. playersBelowGrade counts active players below 60%, including unmeasured zeros. calcTeamGameSenseScore has no current caller found; it is not behind the sample card.
  • supabase.js: getTeamQuizHistory reads quiz_sessions for current roster player IDs, ordered by completion date with no date filter. This audit did not query those production rows.
  • coachAnalytics.jsx: the distinct Team accuracy tile pools correct/total answer rows. A legacy score-plus-session-length fallback approximates counts if result rows are absent. Seven-day windows use stored date strings.
  • screens.jsx: GameSenseReportScreen calculates quiz competencies before fetching coach ratings for a separate profile card. The report unlocks after three quiz sessions.
  • quizResults.js: upsertResult replaces a prior row for the same question ID. An eventual answer can replace a skipped/wrong placeholder; historical rows do not preserve every first response.
Worked-fixture verification and limits

The current pure declarations were extracted from the source with Acorn and evaluated read-only against the invented roster. Legacy recognised IDs were used so the averaging behaviour can be inspected separately from the modern-ID mapping issue.

Actual output: positioning 88%, awareness 50%, weakest awareness, below threshold 4, active players 4, roster 5. Zero-only roster output: active players 0, weakest null.

The 262-question and 28-seed inventory was read locally on 5 September 2026. This is not a production team analysis or a claim of learning efficacy. No scoring code, earned history, database record or assessment weighting was changed. Browser-render review is separate from this code audit.

Proposed source mapping and release safeguards

A versioned registry should bind each exact reviewed question hash to its concept, age scope, primary assessed competency, answer/rubric version and semantic decision identity. Keep the curriculum’s six domains separate from the report’s five competencies. Unknown mappings stay unknown.

  • Preserve legacy scores, rewards and saved records.
  • Include measured zeros while labelling missing and insufficient evidence distinctly.
  • Record first responses prospectively; never manufacture them from old practice-point summaries.
  • Keep draft positioning, coach opinions and observation facts separate from approved tactical assessment.
  • Hide Challenge correctness until the completed play, including score counters that could reveal it.
  • Review age scope, weights, minimum coverage and recency using sample histories before enabling a new GS number.
